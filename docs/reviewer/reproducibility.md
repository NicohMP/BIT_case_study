# Reproducibility (Reviewer Notes)

This project is designed to be reproducible in two senses:
(i) the *background state* (ingestion → filtering → matching → scoring → selection) is generated by a scheduled, deterministic pipeline, and
(ii) the *report* is produced on demand from a persisted, versioned context pack.

All intermediate decisions are written to Postgres tables with explicit version fields, and artifacts are written under `reports/`.

## Prerequisites

- A Postgres database (Supabase-compatible) available via `DATABASE_URL`.
- A `.env` file with at least `DATABASE_URL`. For report generation via Gemini, also set `GOOGLE_API_KEY`.
- Python environment (the repo uses `./venv/bin/python` in examples).

## 1) Database schema

Apply Supabase migrations:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/migrations/20260225210000_add_pm_security_signal_report.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/migrations/20260226170000_add_pm_market_daily_snapshot.sql
```

## 2) Refresh pipeline state (Steps 1→4b)

Run a single refresh to populate:
`pm_event`, `pm_market`, `pm_market_filter_decision`, `pm_market_signal_family_match`,
`pm_market_security_relevance`, `pm_market_security_relevance_selection`.

```bash
./venv/bin/python scripts/run_polymarket_refresh.py \
  --ingest-max-pages 200 \
  --matcher-version matcher_v10 \
  --scoring-version relevance_v5 \
  --persist-selection true \
  --selection-version selected_v1 \
  --run-audit true
```

This writes a pipeline audit under `reports/pipeline_audit_*.md`.

## 3) (Optional) Record daily market snapshots (for Δp)

The Gamma API is spot; movement features require accumulated history. Record one daily snapshot row per market (UTC day):

```bash
./venv/bin/python scripts/record_daily_market_snapshots.py --scope kept
```

After repeated daily runs, Δp can be computed from lagged probabilities.

## 4) Generate one report (Step 5, on demand)

Build a context pack for a ticker:

```bash
./venv/bin/python scripts/build_security_report_pack.py --ticker NVDA
```

Validate the pack (useful when schemas evolve):

```bash
./venv/bin/python scripts/validate_security_report_pack.py --pack reports/context_pack_NVDA_<ts>.json
```

Generate report JSON (Gemini):

```bash
./venv/bin/python scripts/generate_security_signal_report.py --pack reports/context_pack_NVDA_<ts>.json
```

Render Markdown:

```bash
./venv/bin/python scripts/render_security_signal_report_md.py --report-json reports/security_signal_report_NVDA_<ts>.json
```

Audit grounding:

```bash
./venv/bin/python scripts/audit_security_signal_report.py \
  --pack reports/context_pack_NVDA_<ts>.json \
  --report-json reports/security_signal_report_NVDA_<ts>.json
```

## 5) Web UI (minimal local demo)

Run the UI on top of the populated database:

```bash
./venv/bin/python -m uvicorn polyscanner.webui.app:app --reload --port 8000
```

The UI reads from the versioned pipeline tables (Steps 1–4b) and displays persisted reports (Step 5).

## Where to look for evidence

- Pipeline audits: `reports/pipeline_audit_*.md`
- Context packs: `reports/context_pack_<TICKER>_*.json`
- Reports: `reports/security_signal_report_<TICKER>_*.json` and `.md`
- Database tables are queryable by version (`filter_version`, `matcher_version`, `scoring_version`, `selection_version`).
